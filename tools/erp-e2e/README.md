# ERP e2e регресс-скрипты

Живые сквозные проверки против dev-стенда (:3000, workspace «ERP Dev», dev-логин).
TypeScript (директива Антона 26.08: весь наш код — на языках оригинального
Twenty). Изначально были портированы с Python 1:1 (см. git-историю для
`e2e_*.py`, удалены после зелёного паритета шагов на TS-версии).

- `e2e_sales.ts` — цикл продаж: счёт с НДС → проведение → регистр → guard → печать → оплаты → сальдо 0 → сторно с откатом статуса → cancel→edit→re-post (Task 7 T7: тот же номер, регистры верны).
- `e2e_purchases.ts` — цикл закупок: счёт поставщика (−total) → guard'ы документа и строки → оплаты (+amount) → сальдо → сторно → смешанное сальдо AR/AP одной компании.
- `e2e_stock.ts` — цикл склада: 2 поступления (скользящая средняя) → реализация (списание по средней, guard'ы, печать УПД) → перемещение между складами → списание → нехватка остатка (RU-ошибка с именами) → guard отмены поступления в минус → сторно реализации с возвратом остатка.
- `e2e_accounting.ts` — цикл бухгалтерии: поступление → счёт покупателю (НДС 22%) → реализация → оплата → ручная операция (Дт/Кт) → проводки по каждому документу (join через план счетов по коду) → ОСВ (MCP `trial_balance`, обороты Дт=Кт, сальдо ключевых счетов) → lockDate (отказ проведения задним числом и отмены документа в закрытом периоде, RU-ошибка) → импорт банковской выписки 1CClientBankExchange (CP1251, идемпотентность по comment+сумма+контрагент) → сторно ручной операции (glEntry реверс, сумма по voucherId = 0).
- `e2e_mcp.ts` — MCP-протокол целиком (Фаза 8 T1): `initialize` → `tools/list` (все ERP-тулы + платформенные мета-тулы присутствуют с описаниями) → агентский сценарий ЦЕЛИКОМ через `tools/call` (CRUD через `execute_tool`: организация+товар+компания+счёт со строкой → `post_document` → `trial_balance`/`find_many_gl_entries` (проводки) → `cancel_document` → ASSERT `docStatus DRAFT` (Phase 7 T7 — cancel не терминален)) → `lookup_party_by_inn` без `DADATA_API_KEY` (грейсфул-ошибка, не 500) → негативы: `post_document` без прав (restricted-role API key) и на несуществующий/«чужой» recordId → отказ; CRUD-запись в регистр `glEntry` через MCP → отказ guard'ом. Детали endpoint/авторизации — `docs/erp-design/mcp-surface.md`.
- `lib/e2e-client.ts` — общие GraphQL/MCP-хелперы (`gql`, `gqlRaw`, `login`, `mutationNames`, `findName`, `money`, `getExtensionMessage`, `mcpRpc`/`mcpToolCall`), переиспользуются всеми скриптами.

Запуск (Node 24 обязателен через volta — глобальный Node 22 x64-on-arm64
ломает нативные модули):

```
volta run --node 24.5.0 --yarn 4.13.0 -- npx tsx tools/erp-e2e/e2e_sales.ts
volta run --node 24.5.0 --yarn 4.13.0 -- npx tsx tools/erp-e2e/e2e_mcp.ts
# ... аналогично e2e_purchases.ts / e2e_stock.ts / e2e_accounting.ts
```

`tsx` уже в devDependencies корневого `package.json` — отдельная установка не
нужна. Сервер должен отвечать на `/healthz`. Скрипты самонастраиваются
интроспекцией GraphQL-схемы (мутации) и создают собственные данные каждый
прогон (случайный суффикс в именах) — прогоны друг другу не мешают.

`e2e_accounting.ts` переиспользует серверную утилиту кодирования CP1251
(`packages/twenty-server/.../erp-accounting/utils/decode-cp1251.util.ts`
`encodeCp1251`) вместо добавления `iconv-lite` как зависимости — та же
причина, что и в самом сервере (см. комментарий в этом файле).
