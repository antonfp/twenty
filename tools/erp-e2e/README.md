# ERP e2e регресс-скрипты

Живые сквозные проверки против dev-стенда (:3000, workspace «ERP Dev», dev-логин).

- `e2e_sales.py` — цикл продаж: счёт с НДС → проведение → регистр → guard → печать → оплаты → сальдо 0 → сторно с откатом статуса.
- `e2e_purchases.py` — цикл закупок: счёт поставщика (−total) → guard'ы документа и строки → оплаты (+amount) → сальдо → сторно → смешанное сальдо AR/AP одной компании.
- `e2e_stock.py` — цикл склада: 2 поступления (скользящая средняя) → реализация (списание по средней, guard'ы, печать УПД) → перемещение между складами → списание → нехватка остатка (RU-ошибка с именами) → guard отмены поступления в минус → сторно реализации с возвратом остатка.
- `e2e_accounting.py` — цикл бухгалтерии: поступление → счёт покупателю (НДС 22%) → реализация → оплата → ручная операция (Дт/Кт) → проводки по каждому документу (join через план счетов по коду) → ОСВ (MCP `trial_balance`, обороты Дт=Кт, сальдо ключевых счетов) → lockDate (отказ проведения задним числом и отмены документа в закрытом периоде, RU-ошибка) → импорт банковской выписки 1CClientBankExchange (CP1251, идемпотентность по comment+сумма+контрагент) → сторно ручной операции (glEntry реверс, сумма по voucherId = 0).

Запуск: `python3 tools/erp-e2e/e2e_sales.py` (сервер должен отвечать на healthz). Скрипты самонастраиваются интроспекцией и создают собственные данные каждый прогон.
